Behavior rules

● Cache key: model + the full message list sent to the LLM (system prompt + history + new

message). The same first message sent in a new session must return LLM_CACHE the second
time. A different message must never come from cache.

● Cache hit: returns the identical reply text. Tokens are the usage stored with the cached

response; key_id is null.

● Multi-turn: history is stored in SQLite per session_id. The client sends only the new

●

●

message.
Tokens: per request, never a running total. Two equal-length first messages in two new
sessions report about the same input_tokens.
Latency: latency_ms is an integer in milliseconds. A cache hit must be faster than a live
call.

4. Failover test hook

POST /chat must support an X-Simulate-Failure request header. It makes chosen keys fail inside
that one request only, so failover can be demonstrated on demand without exhausting real keys.

X-Simulate-Failure: key_1=429
X-Simulate-Failure: key_1=429,key_2=500
X-Simulate-Failure: *=429

●

Format: comma-separated <key_id>=<status> pairs; * means every key. Statuses: 429,
500, 502, 503.

● Effect: each listed key behaves as if its provider returned that status, for this request only.
● Switch: honored only when ENABLE_FAILURE_SIMULATION=true, which must be set on your

deployed backend.
